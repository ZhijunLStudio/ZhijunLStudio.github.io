关键发现

共同局限

  • 全部聚焦模拟单一域，无跨域视角
  • 全部是学术原型，无工程化实现
  • 无 Adapter 协议概念，工具硬编码绑定
  • 不做版图、不做后仿真、不做 MC/Corner
  • 无状态管理系统

IC Agent OS 的差异优势

  • 覆盖模拟全流程 6 Stage（含版图/后仿/MC/Signoff）
  • LLM + BO 混合决策：LLM 策略 + Stagnation→BO 切换
  • 3 级状态管理支撑跨 Stage 回跳
  • Adapter 协议：仿真器可插拔
  • VLM 透明调度：波形/版图/DRC 视觉分析
最值得深入分析的竞品——AnalogSAGE：其 3 Agent 分层 + 4 层记忆架构与 IC Agent OS 设计理念高度一致。论文 arXiv:2512.22435 包含完整的记忆系统设计和 BO+SPICE 循环细节。但其"记忆"偏重 Agent 内部组织，IC Agent OS 强调 Snapshot/Delta/Action 作为所有操作的载体——这是关键理念差异。

通用 BO 框架（可直接集成）

框架维护方特点IC Agent OS 适用场景
BoTorch + Ax Meta (PyTorch) 多目标、多保真度、约束、异步、自定义采集函数 首推——多保真度支持（高/低精度 SPICE 切换）；PyTorch 原生，易于集成

BO 模块的关键决策：模拟电路的器件参数是混合变量（连续 W/L + 离散 finger/Multiplier）。TuRBO（Trust Region BO）在混合变量场景下效果好于标准 GP-BO。建议 IC Agent OS 的 BO 模块基于 BoTorch+Ax，并集成 TuRBO 策略处理离散变量。

国产 EDA 与 IC Agent OS 的战略协同

国产厂商的痛点

  • 数字后端工具替代率 <20%
  • PDK 生态严重依赖国际三大厂
  • 用户习惯难以迁移
  • AI 能力分散，缺乏统一的优化框架

  • Adapter 协议让国产工具获得AI 优化能力
  • IC Agent OS 成为国产工具的用户获取渠道
  • 优化闭环积累的轨迹数据反哺工具改进
  • 开源社区降低信任门槛

闭环深度 单 Stage（仅前仿优化）OR 单方向流程（RTL→GDS，不回头） 6 Stage 跨阶段回跳：后仿指标退化→回 Stage 2 改 Sizing OR Stage 3 改版图 空白

工程空白：5 个可优先突破的方向

Gap 1 SPICE 收敛诊断库
无开源方案系统性地诊断 SPICE 不收敛原因（振荡/高阻抗节点/浮空节点/Gmin stepping 失败）。ngspice 仅给出错误码，不做根因分析。IC Agent OS 的 Self-Debug Loop 强依赖此能力。
Gap 2 SPICE 模型分析器
无开源 Python 库解析 BSIM/PSP 模型参数、提取 Vth/gm/Idsat 等关键设计参数、进行跨 PDK 对比。PDK 摘要引擎需要此能力。
Gap 3 统一模拟 EDA 工作流引擎
无将 Xschem→Ngspice→Magic→Netgen→KLayout 全工具链串联 + 经验追踪 + BO 回环的平台。SiliconCompiler 覆盖数字但不覆盖模拟。
Gap 4 设计轨迹数据库
AnalogSAGE 的 4 层记忆是最接近的设计，但仍为学术原型。无生产级的"设计决策→结果→经验"持久化与检索系统。
Gap 5 LLM+BO 工程化混合框架
ADO-LLM/ORFS-agent 验证了 LLM+BO 混合的有效性，但均为学术一次性脚本。无工程化的"LLM 主决策→Stagnation 检测→BO 自动接管→结果回注 LLM 上下文"框架。
