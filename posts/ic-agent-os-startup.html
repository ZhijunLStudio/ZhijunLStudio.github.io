BENCHMARK

为什么选 AnalogGym？

选择一个标准 benchmark 是项目启动的第一步。它决定了我们能跟谁比、怎么比、以及结果能否被学术界认可。

AnalogGym 是什么

AnalogGym 是第一个面向模拟电路自动综合的标准化测试套件，发表于 ICCAD 2024（顶会，Invited Paper），由复旦大学、北京大学、MIT 等多个团队联合推出。它的定位类似计算机视觉的 ImageNet 或强化学习的 OpenAI Gym——在它之前，每个做模拟电路优化的团队各用各的电路、各用各的 PDK、各用各的指标，根本没法横向对比。

为什么选它

✅ 标准化，可复现

每个电路自带 netlist + testbench + PVT corner 定义 + 指标提取脚本。别人跑出来什么结果，我们同样环境跑一遍，数字可以直接横向对比。

✅ 开源工具链

AMP 和 LDO 共 21 个电路支持 ngspice + sky130 PDK，全部开源，无需商业 License。学生可以自己在笔记本上跑通完整流程。

✅ 覆盖面广

17 个 AMP 跨多种拓扑结构（两级/共源共栅/嵌套 Miller/class-AB），不同复杂度、不同补偿策略——真正测试"统一架构"能否 work。

✅ 有竞品参照

AnalogGym 论文本身跑了 GCNRL、WEIBO、cVTS、SMEA、MTEA 5 个 baseline。我们可以把 AnalogSAGE 也在上面跑一遍，得到完整的竞品数据。

P1 聚焦 21 个 ngspice+sky130 电路。剩下 11 个电路（Sensing/VR/PLL）需要商业 EDA License，P2/P3 阶段通过 Adapter 对接 Spectre/HSPICE 后自然会覆盖。P1 先用 21 个电路证明架构可行性。

IC-Agent-OS 要做的，就是给定这样一个任务，自动完成 Spec → Sizing → 仿真 → 对比 Spec → 调整 Sizing → 重新仿真 → ... → 全部指标达标。

PROJECT GOAL

项目目标与定位

一句话目标：在 AnalogGym 的 21 个 ngspice+sky130 电路上，基于 OpenCode + SkillOpt 调度，同一套工具和技能跑通全闭环，平均仿真次数优于 AnalogSAGE 同级水平 50% 以上。

🔧 工具化

IC-Agent-OS = OpenCode + 一组 EDA 专用工具（Adapter/Optimizer/State）+ 一组可进化的技能文档。OpenCode 负责 Agent 循环，我们负责领域能力。

🧬 Skill 调度

不做 hardcode 的优化流水线。SkillOpt 机制管理技能的选择、评估、进化——什么电路加载什么技能、用哪个优化策略、什么时候触发进化，全由调度器决策。

📐 标准化对比

所有实验在 AnalogGym 标准 benchmark 上运行，所有数字公开可复现。不自己造 benchmark，不和自己的旧版本比，只和竞品在同一个电路上比。

为什么选 OpenCode？

不重复造轮子

Agent 循环（LLM 调用、工具路由、上下文窗口管理、错误重试）是通用能力。OpenCode 已经做得很好了，我们不重新发明。

Skill 原生支持

OpenCode 的 skill 系统（.md 文件作为 Agent 指令）恰好是 SkillOpt 的操作对象——我们把 SkillOpt 接在 OpenCode 外边做 skill 的评估和进化，不改 OpenCode 一行代码。

开源 + 可定制 Tool

OpenCode 允许注册自定义 Tool。我们的 Adapter/Optimizer/State 作为 Tool 接入，OpenCode 根据 Skill 指令决定何时调用哪个 Tool。

三个自定义 Tool

Tool调用时机输入输出
Adapter Tool OpenCode 决定"需要测一下当前设计" netlist + analyses 列表 + PDK 配置 StructuredMetrics 或 SimError
Optimizer Tool OpenCode 决定"需要新的参数候选" ParamSpace + Constraints + History + Hint Proposal { params + rationale }
State Tool 每次迭代后自动记录 / OpenCode 需要查历史 (Snapshot, Diff, KnowledgeQuery) 三种操作模式 对应三种模式的不同输出

一条典型任务是怎么执行的

# OpenCode 加载 SizingSkill.md 后，Agent 自主决策执行以下循环：

1. [OpenCode] 读取 Spec: Gain≥60dB, GBW≥10MHz, PM≥60°, Power≤1mW
2. [OpenCode] 调用 InitSkill 获取初始参数起点
3. [OpenCode] 调用 Adapter Tool: simulate(netlist_template + init_params)
4. [Adapter Tool 返回] { gain: 48dB, gbw: 8.2MHz, pm: 72°, power: 0.6mW }
5. [OpenCode] 对比 Spec → gap: gain 差 12dB, gbw 差 1.8MHz, pm 已达标
6. [OpenCode] 调用 Optimizer Tool: propose(gap, history, SizingSkill)
7. [Optimizer Tool 返回] Proposal { M3_W: 8→14u, M1_W: 5→8u, rationale: "..." }
8. [OpenCode] 渲染新 netlist → 回到步骤 3
   ...
N. [OpenCode] 全指标达标 → 调用 State Tool 记录轨迹 → 返回最终设计

# 这一轮结束后，SkillOpt Scheduler 在后台：
#   - 收集本轮轨迹数据
#   - 当积累足够新数据后触发 Skill 进化迭代
#   - 在 held-out 电路上验证新 Skill，严格提升才接受

SKILL EVOLUTION

Skill 自进化——核心差异化能力

集成了微软 SkillOpt（2026.05）的训练范式。SkillOpt 在这里的角色不是"一个外挂优化工具"，而是整个系统的调度核心——它管理哪些 Skill 被加载、什么条件触发进化、以及新 Skill 能否上线。

可进化的 3 个 Skill

📄 SizingSkill.md

内容：参数调整策略——"增益不够时优先查什么"、"带宽和相位冲突时怎么 trade-off"

初始版本：教科书级启发式规则

进化方向：从仿真轨迹提炼条件-动作规则，精炼到特定拓扑的特定阶段

📄 DiagnoseSkill.md

内容：仿真失败诊断——收敛失败/振荡/工作点异常的分类判断和修复路径

初始版本：ngspice error log 常见模式匹配

进化方向：从实际失败案例学习新的错误模式和修复路径

📄 InitSkill.md

内容：不同拓扑的初始 Sizing 推荐——不随机，给有依据的起点

初始版本：AnalogGym 各拓扑的默认参数值

进化方向：跨电路迁移——NMCF 的经验可 warm-start DFCFC1

SkillOpt 调度器如何工作

# scheduler.py —— 李志军负责
class SkillOptScheduler:
    """
    不阻塞 OpenCode 主流程。后台异步运行。
    当积累够 minibatch_size 条新轨迹后，触发一轮进化。
    """
    def on_task_complete(self, task_id, trajectory):
        self.buffer.append(trajectory)
        if len(self.buffer) >= self.minibatch_size:
            self.evolve()

    def evolve(self):
        for skill in [SizingSkill, DiagnoseSkill, InitSkill]:
            # 1. Rollout: 在训练电路上收集当前 skill 的表现
            baseline = self.evaluate(skill, self.train_circuits)

            # 2. Reflect: 分析成功/失败轨迹，找模式
            patterns = self.reflect(self.buffer, skill)

            # 3. Edit: LLM 提出 ≤4 次编辑操作（文本学习率）
            candidate = self.edit(skill, patterns,
                                  rejected=self.rejected_buffer[skill.name])

            # 4. Gate: 在 held-out 验证电路上评估
            candidate_score = self.evaluate(candidate, self.val_circuits)

            if candidate_score > baseline:
                skill.update(candidate)    # 接受 → 替换线上 Skill
            else:
                self.rejected_buffer[skill.name].add(candidate.edits)  # 负梯度
验证集 = AnalogGym 中的 held-out 电路。比如 21 个电路中固定 hold-out 4 个，不参与日常实验，只在 Gate 阶段用。这是 SkillOpt 最核心的机制——没有严格门控，Skill 进化 = 随机漂移。Ratchet 论文的结论也完全一致：LLM 自己写的技能几乎没提升（+0pp），但加上严格门控后可以持续提升。
